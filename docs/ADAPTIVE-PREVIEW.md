# Adaptive preview memory

Editing, playback, thumbnails and library previews use disposable image copies. The document's image URLs, encoded bytes, dimensions and anchor coordinates are unchanged. Preview bitmaps expose their original `naturalWidth`/`naturalHeight`; their actual `width`/`height` describe allocated pixels. GPU background uploads use the actual pixel dimensions.

`PlaybackResources` enables this with `preview: true`. It inspects PNG dimensions before decoding, estimates the needed pixels from the figure's scale and view resolution, deduplicates URLs, distributes its decoded-image allowance across the current draw, and discards obsolete variants before replacing them. The editable canvas uses a serial worker with a coalesced latest request. Zoom can request more detail; stale work cannot overwrite a replacement document. Empty vector-only scenes need no image worker.

For ordinary non-interlaced PNGs, `preview-image.mjs` streams decompression through two scanline buffers and samples into the bounded preview. It supports PNG filters, packed grayscale/palette samples, RGB/RGBA, 16-bit samples and transparency. Embedded colour profiles and interlacing use the browser decoder to preserve their interpretation. Other formats also use the browser decoder. Browser resizing does **not** guarantee bounded transient decoder memory for those fallback cases.

Playback retries a frame at half raster resolution when preparation exceeds its allowance, releasing failed packet bitmaps and cached raster originals between attempts. It retains the chosen raster detail for the current view to avoid repeating expensive failed attempts on every frame; a view/document revision resets it. Ordinary vectors stay as exact vector records throughout pixel-pressure recovery, and vector-only frames report full quality. Per-figure vector rasterization is reserved for cases where the vector records themselves exceed their allocation. Figures remain separate, with their IDs, transforms, visibility and painter order. Cancellation yields use scheduler/MessageChannel tasks, avoiding timer clamping.

Packet admission uses 80% of the existing CPU cache allowance, leaving headroom for GPU backgrounds. The 64 MiB vector-buffer guard applies to vector records, not to the sum of independently allocated textures. Raster-original retention scales up to 128 MiB, capped at one quarter of the hardware-based frame allowance. The earlier blanket 64 MiB packet cap, 32 MiB raster cache and conversion of all vectors on any pixel-budget retry caused severe full-animation regressions; short runs starting after the pressure frame did not reproduce them.

The editor estimates unique figure texture residency before building a layout and reduces raster detail if necessary. Its vector geometry, handles, poses and history remain available. An incremental edit that exceeds the texture target falls back to planning the complete layout. The UI shows “Reduced preview quality” when memory pressure reduces detail.

Supported single glyphs share quantized alpha masks across poses and colors. The editor counts the actual unique mask dimensions at each candidate quality, including when a very large object changes from the complete raster path to a mask as detail is reduced. Worker vector commands have a separate allocation of at most 32 MiB (one eighth of the frame allowance) and 4,096 entries. Worker path-only scratch surfaces up to 262,144 pixels use CPU rasterization; larger surfaces and image compositing retain acceleration. Both scratch contexts release pixels between captures and do not expand the retained raster budget.

`previewMemoryPlan()` centralizes hardware-based retention allocations. CPU/GPU frames, decoded images, raster originals, editable textures and thumbnails have separate allocations within that policy. Existing shared artwork and measured prefetch eviction remain active. This is a policy for retained caches, **not** a hard cap on total process memory: the document, temporary transition copies, browser decoding internals, graphics-driver allocations, and export output surfaces also consume memory. Required live resources can temporarily exceed retention targets during atomic scene transitions.

Raster export explicitly uses `preview: false`. It loads original images one object at a time while retaining the native brush state and painter order. Large output frames render through 1024-pixel tiles with guard pixels, bounding opacity/outline scratch surfaces. The final output canvas keeps the requested size. SVG and the existing “No smoothing” path retain their existing implementation and original assets. Individual source decodes, the final output canvas and those existing export paths still have browser/format limits; this change does not promise arbitrary-size exports within a fixed amount of RAM.
