# Asset library

The Library panel (`src/user-library.mjs`, `src/styles/features/library.css`) has two sources, switched at its top: **My library**, the desktop library of saved assets and folders, and **Public library**, the curated catalogue on stykanimate.com (below). Under the switch sit Search, a **Show** kind filter (All, Figures, Movieclips) and the library's **⋯** menu (New folder, Add selection, Refresh, Show in folder, Preview background, Rig examples). The row below names where you are: the folder path with the item count and **New folder** in My library, the website in Public library. The cards form one listbox with a single tab stop; the foot is pinned under them: the status line, then **Add selection** (the website link in Public library). This implements experience.md §5.5 with the website's library as the second source; the spec's *This project* and *Examples* live in the Add menu and the ⋯ menu's Rig examples.

Select one or more figures, or a movieclip, and choose **Add selection** in the Library's foot or **Add to library** in the Properties footer. The same command is in the canvas context menu and Selection actions. Assets are saved in the folder currently open in My library.

- Drag a figure, set, or movieclip from Library onto the canvas to insert it at the pointer. Double-click or Enter places it at the scene center. Undo removes the insertion in one step. Folders stay in the library.
- Drag assets or folders onto a folder card or a part of the folder path to move them, with a highlighted destination and a move label. Escape cancels a drag; holding near the list edge scrolls it. A folder cannot be moved into itself or its descendants.
- Every card action is in its **⋯** menu, which shows on hover, focus and the selected card (always under touch), and in its right-click menu: Insert or Open, Rename, Move to…, Show in folder and Move to Recycle Bin. Right-click empty library space for the library's own actions. Arrow keys move across a row or to the nearest card above or below; Enter opens or inserts, F2 renames inline, Delete opens the removal dialog, and Shift+F10 opens the menu. Renaming preserves the native extension.
- Thumbnails automatically choose a light, neutral, or dark checkerboard from visible artwork colors so white and dark assets remain readable in either app theme. **Preview background** in the ⋯ menu also offers Light and Dark overrides. These backgrounds do not alter artwork or saved transparent PNGs.
- Hover over a movieclip to play its actual editable animation, including nested clips and native timing, in a looping thumbnail. The preview uses a stable fit of sampled motion, a progress line, and a single contrast background sampled across the clip. Leaving, scrolling, changing panels, dragging, or losing app focus stops the preview and releases its worker. Hover rendering is capped at 24 FPS while preserving the clip's playback duration.
- Figure sets preserve their relative positions, pose, internal attachments, and draw order. A selected child without its parent is saved detached at its displayed position. Movieclips retain their nested editable animation and start playing at the insertion frame.

The desktop library is in the OS Documents folder at `StykAnimate/library`, including redirected Documents/OneDrive folders. The Windows setup creates that folder for the current user; first launch also creates it for portable installs and other users. Updates and uninstall retain the user's library.

Single figures and sets use native, compressed `.stkz` files; movieclips use `.stykmov`. Each file has a transparent 320 × 320 PNG sidecar (`name.stkz.png`) and small optional metadata (`name.stkz.json`). Rename and Move carry the sidecars along. Files copied into the library without previews have their previews generated when visible. Refresh, switching to Library, or returning focus to the app detects external changes. Copy the sidecars too to avoid regenerating previews.

Version 0.4.0 extends `.stkz` to contain a set of figures in one pose. Earlier app versions can still open single-figure files but do not support sets.

Preview rendering and native export run in workers. Hover playback decodes the native file in its own worker with one frame in flight and no retained rendered-frame sequence. Native transfers use acknowledged 256 KiB chunks and commit complete files exclusively without overwriting another asset. Colliding names gain a numeric suffix. Library IPC accepts only paths inside the library, rejects links and traversal, and never accepts renderer-selected absolute filesystem paths.

Verification: `npm run test:library`, `node --test tests/library-preview.test.mjs`, `node tests/library-panel.browser.mjs` (with `npm run serve`), `node tests/user-library-ux.desktop.mjs`, `node scripts/smoke-public-library.mjs` (after building the catalogue), `node scripts/smoke-library-drag.mjs`, `npm run test:library:desktop`, and `node scripts/smoke-library.mjs --packaged`. `STYK_LIBRARY_DIR` and `STYK_USER_DATA_DIR` isolate automated test storage. `STYK_PACKAGED_EXECUTABLE` selects a versioned release for packaged tests.


## Public library

The website publishes a curated, read-only catalogue at `/library/`: `catalog.json`, `files/<id>.stkz` (or `.stykmov`) and `previews/<id>.png`. `scripts/build-public-library.mjs --out <site>/public/library` builds it: each asset is written with the app's native container, imported again in the served app and previewed by the same library preview a saved asset gets (320 × 320, transparent). The catalogue (format `stykanimate-public-library`, version 1) lists packs and items with a kind, size, SHA-256 and matte. Today it holds the app's own rig examples (Mechanisms and 3D shapes). The AssetReleases packs are sold separately and are not published.

- Choose **Public library** in the panel. Assets are grouped by pack; Search and Show filter them. Double-click, Enter or a drag to the canvas inserts an asset exactly like a saved one, in one undo step. Its ⋯ menu adds **Save to My library** (into the folder open in My library, with its preview) and **View on stykanimate.com**.
- `desktop/public-library.cjs` owns every request in the main process: only `https://stykanimate.com/library/` is contacted, the catalogue is validated strictly and reused for ten minutes, responses are size-bounded (catalogue 512 KiB, preview 1 MiB, file 8 MiB), redirects are refused, previews must be PNG, and a file reaches the renderer or the library only after its size and SHA-256 match the catalogue. Previews (160) and files (32 MiB) are cached in memory only. Nothing about the user or their projects is sent.
- The website's **Open in StykAnimate** is `stykanimate://library/<id>`. The main process accepts only catalogue-shaped ids, keeps the link until the workspace takes it (so a link that starts the app is not lost), and the Library opens on Public library with the asset selected and focused. The link never writes files or edits the scene by itself.
- Without a connection the Public library says so with **Try again**; an already shown catalogue stays usable. The browser build links to the website instead.
- `STYK_PUBLIC_LIBRARY_URL` points the app at a loopback server for tests; any other address is refused.

## Copy between projects

Use **File → New window**, or launch StykAnimate again, to keep another project open. Copy or cut selected figures on the canvas, switch windows, and paste on the destination canvas. Copy frames in either timeline and paste in the destination timeline. The usual Ctrl+C, Ctrl+X, and Ctrl+V shortcuts (Command on macOS), timeline buttons, and context menus use the shared desktop clipboard.

Copies include figure definitions, embedded media, internal attachments, and movieclip animation. Timeline transfers preserve exposures, easing, scene/camera data when selected, and create missing destination layers. Paste is one undoable action. Copying text in another application replaces the shared clipboard normally. Each open desktop workspace has separate recovery data.

Verify native cross-window transfers and mouse drag placement with `node scripts/smoke-shared-clipboard.mjs`; model and bounded native transfer tests are in `tests/shared-clipboard.test.mjs`.
